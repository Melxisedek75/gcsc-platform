# XPR Testnet project access and bidding: intent

The installed 0.1.11 Contractor can view a published job but cannot bid without a project-specific paid entitlement. The existing 50 XPR generic Lead Token payment creates a token receipt, not that entitlement. The payment must not be restored as a misleading shortcut.

Goal: let a verified Contractor purchase access to one open job with a wallet-approved XPR Testnet transfer, verify the exact transfer on the server, grant access only after confirmation, then submit a normal server-backed bid. No Mainnet payment, automatic signature, fabricated grant, or owner-side acceptance is in scope.

The owner confirmed the test terms: 50.0000 XPR once per project to the configured Testnet recipient, then no separate fee for submitting a bid. Each transfer still requires the owner to inspect and authorize the exact WebAuth request on the device.
